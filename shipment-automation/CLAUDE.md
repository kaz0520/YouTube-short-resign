# 手書き出荷リストのデジタル化＋Excel管理 — 設計メモ（Claude向け）

手書きの出荷リスト画像を、客先・商品・個数・在庫変動として構造化し、Excelで管理する
業務を段階的に自動化するプロジェクト。初心者ユーザーと伴走する前提。

## 決定事項（ツール選定）

| 工程 | 採用 | 備考 |
|---|---|---|
| 画像→客先/商品/個数の抽出 | **Claude本体の画像読み取り** | Google Vision APIは不採用（OCR+解析を1ステップ化するため）。APIキー不要 |
| 一時保存（CSV/JSON） | プロジェクトフォルダ配下 `data/` | Git管理で履歴を残す |
| Excel（在庫・客先）読み書き | **Google Drive コネクタ**（接続済み） | GWSローカルCLIは不採用。MCPで足りるため |
| ローカルでの.xlsx生成/整形 | `xlsx` スキル | Driveがスプレッドシートでなく実.xlsxの場合 |

## 中核エンジン: 既存スキル `advanced-shipping-note-to-excel`

ユーザーがCoworkで作り込んだスキルを本プロジェクトの**中核**に採用。
これ1つで「画像→客先/商品/個数の構造化→見本準拠の出荷リストExcel生成」まで完成済み。
- 製品マスタ辞書で表記正規化、配送区分（福山/ヤマト/混合=佐・直・引）でシート分割
- セル書式（結合・罫線・プルダウン・折り返し）、未確定は「要確認」黄セル
- 行ずれ防止手順・誤読パターン辞書を内蔵（サンワ製品／実業務にチューニング済み）
- 生成スクリプト: skill内 `scripts/generate_shipping_excel.py`
- 命名: `出荷リスト_月_YYYYMMDD_NNN.xlsx` / 画像は `MMDD_配送区分`

→ 当初フローの「Google Vision + 解析 + Excel書込」は、このスキルで置換・統合される。

## ロードマップ（スキル採用後に更新）

| Phase | やること | 状態 |
|---|---|---|
| 1 | このスキルで実画像1枚→出荷リストExcel生成を通す（動作確認） | 着手中 |
| 2 | 製品マスタ辞書(製品マスタ.xlsx)を用意/接続し正規化精度を上げる | 未 |
| 3 | 在庫（帳面製品リスト）と突合し在庫数量を自動更新（当初フローの在庫管理） | 未 |

## データ構造（Phase 1 の抽出フォーマット案）

CSV列: `記録日, 客先名, 商品名, 出荷個数, 在庫変動(推論), 確信度, メモ`
- 確信度: high / low（誤認識の疑いがある行は low + 修正候補をメモに）
- 在庫変動: 出荷個数ぶんのマイナス。基準在庫が分かれば残数も算出（Phase 2）

## ファイル構成

```
shipment-automation/
  CLAUDE.md        … このファイル（設計・決定事項）
  PROGRESS.md      … 作業ログ
  docs/            … 手順書・調査結果
  data/            … 抽出したCSV/JSON（一時保存）
```

## 注意（外部データ操作）

- Excel（本番の在庫データ）を更新する前に、必ず更新前ファイルのバックアップをローカルに取得してから実施する。
- Drive上のファイルを上書きせず、更新版は別名 or 版管理で残すことを検討。
